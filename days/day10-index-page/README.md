# Day 10: Index page and repo check

**What:** Scans every `days/dayNN-name/` folder, builds `INDEX.md` (a table of all tools grouped by roadmap phase) and checks the repo conventions, so CI catches a forgotten README row or a half-finished day.
**Why:** With 100 tools the repo needs one page a newcomer can scan, and the daily rules (a README with What and Why, a tool, an example, a test) need to be enforced by a machine rather than by memory.

## Usage
Rebuild the index after you add or edit a day (it writes `INDEX.md` in the repo root):
```bash
python days/day10-index-page/tool.py
```
Check without writing. This is what CI runs, and it exits with 1 if anything is wrong:
```bash
python days/day10-index-page/tool.py --check
```
```
checked 16 days: 0 errors, 0 warnings
```
(`example/check_output.txt` is the real output on this repository when it was written. Day 1 is the template, so the 16 day folders from Day 2 on plus Day 1 make the 17 days in the index.)
The generated page is [`INDEX.md`](../../INDEX.md).

| Option | Meaning |
|---|---|
| `--check` | do not write, exit 1 on errors or if `INDEX.md` is stale |
| `--root PATH` | repository root (default: this repository) |
| `-o PATH` | index file to write or check (default: `INDEX.md` in the root) |

## What it checks
Errors (these fail CI):
- the folder has no `tool.py` or `README.md`
- the README does not start with `# Day N: Title`, or `N` does not match the folder number
- the README has no `**What:**` or `**Why:**` line, or still has the template placeholder text
- two folders use the same day number
- the main `README.md` does not link a day folder, or its streak badge does not show the latest day
- a project skill (`.claude/skills/*/SKILL.md` or `.agents/skills/*/SKILL.md`) breaks the Agent Skills format: no frontmatter, an unknown field, a name that is not lowercase with single hyphens or does not match its folder, a missing or over-long (more than 1024 characters) description, or a `metadata.version` that is not a quoted number
- `INDEX.md` is out of date (only with `--check`)

Warnings (these are shown but do not fail CI): no files in `example/`, no `test_*.py`, or no `AGENTS.md`.

## Method
- The title, What line and test presence are read from each folder. Table text is shortened at a word boundary and `|` is escaped.
- Phases come from the roadmap (Days 1-10, 11-20, ...). Phases with no days yet are left out. Day 1 is the repo template and is added as a fixed row.
- The output has no dates or counters beyond the day count, so running it twice gives identical files. That is what makes the `--check` comparison reliable.

## Daily workflow
1. `python tools/new_day.py N slug` creates the folder and updates the main README table and badge.
2. Write the tool, test and README, and add a row to the "What is in it so far" table in `README.md`.
3. `python days/day10-index-page/tool.py` to refresh `INDEX.md`, then commit.

## Test
```bash
pytest days/day10-index-page
```
The tests build small fake repositories to cover every error and warning, and also check that this repository passes its own rules.

## Limitations
- It checks structure, not quality. A README can pass with a one-line What.
- `INDEX.md` must be regenerated by hand after editing a README. If CI says it is stale, run the command above and commit the result.
- The phase names are fixed in the script. Edit `PHASES` if you change the roadmap.
- The "Tests" column says whether a `test_*.py` file exists, not how many tests it has.
